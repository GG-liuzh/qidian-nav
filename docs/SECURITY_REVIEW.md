# 首轮界面与安全改进

日期：2026-09-15。范围：当前 Vue / FastAPI 代码、SQLite / PostgreSQL、部署模板与依赖。测试使用隔离数据，没有修改真实账号或公开任何现有资料。

## 本次修复

| 问题 | 原来的行为 | 本版行为 |
| --- | --- | --- |
| 目录与设置拥挤 | 全量目录和多个管理入口堆在侧栏，设置内容集中在长页面 | 目录独立滚动、搜索、逐级折叠；管理入口收拢到按用途分组的设置面板，手机使用分类选择器 |
| 快捷入口、环境过多 | 快捷入口和环境按钮持续占用主内容区域 | 快捷入口默认显示 6 个，可展开及进入整理模式；超过 4 个环境使用选择器 |
| 账号列表泄露明文 | GET 账号列表直接解密并返回用户名，停用 / 待核实账号也如此 | 列表用户名固定为 null；用户名和密码只在有权限且状态有效时通过访问接口返回，并记审计；页面展示 20 秒后清除 |
| 公开数据越界 | 停用入口仍返回 URL；登录后的非成员可通过详情获得比游客更多的内部字段 | 游客与登录后的外部访问者共用公开字段白名单；停用 / 删除的入口和停用环境被过滤，全部入口关闭后整个资源停止公开 |
| 搜索与已保存引用泄露 | 公开搜索复用含隐藏网址的索引，收藏 / 快捷入口可能继续引用停用地址 | 公开搜索只查询公开字段和可见地址；收藏、访问记录、快捷入口及直接按 ID 访问重新检查当前权限 |
| 重置链接未失效 | 修改密码或使用恢复码后，之前的管理员重置链接仍能修改密码 | 所有密码变更均撤销现有会话和未使用的重置链接；停用用户或改变超级管理员身份也撤销相关链接 |
| 跨空间副作用 | 在一个空间降级管理员会撤销其在其他空间的邀请 | 邀请撤销限定在当前空间，其他空间的角色与邀请独立 |
| 密码确认缺少限流 | 已登录的密码确认接口可被反复尝试 | 修改密码与换发恢复码共用按账号计数的限流，失败尝试同样计数 |
| 错误响应缺少安全头 | 来源校验等提前拒绝的响应未经过统一安全头处理 | 提前拒绝和服务器异常同样禁止缓存并带安全头，异常不向客户端返回内部详情 |
| 生产配置易误用 | 开发配置可被直接用于公网 | 生产模式要求 Secure Cookie、限流、明确域名与 HTTPS 来源；部署模板默认仅允许邀请注册 |
| 长网址无法保存 | 编辑器把完整网址放入最多 200 字符的关键词搜索，导致合法长链接保存失败 | 使用独立的精确网址查询参数，支持与保存接口相同的 4,096 字符限制 |
| 已知依赖问题 | cryptography 46.0.7、旧 pip / setuptools 被依赖审计报告 | 升级并固定 cryptography 50.0.0；更新安装工具与 Docker 构建；验证旧版本密文仍可解密 |

## 现在的访问边界

| 身份 | 能读取的链接 | 能读取的业务账号 | 能维护什么 |
| --- | --- | --- | --- |
| 未登录 | 明确公开且有效的链接与入口 | 无 | 无 |
| 独立个人账号 / 空间外部用户 | 自己的个人资料与明确公开的链接 | 自己的私人账号 | 自己的个人资料 |
| 普通成员 | 当前有效空间的内容、自己的个人资料与公开内容 | 当前空间中有效的共享账号，以及自己的私人账号 | 自己的个人资料；团队变更可提交建议 |
| 业务维护人 | 同上 | 同上 | 当前空间的链接与共享账号，以及自己的个人资料 |
| 空间管理员 | 同上 | 同上 | 当前空间的目录、环境、成员、邀请、公开设置及内容 |
| 站点超级管理员 | 所有有效空间；个人资料接口仍按所有者隔离 | 所选有效空间的共享账号，以及自己的私人账号 | 站点用户、空间状态与账号恢复等站点管理功能 |

当前产品采用**空间角色**授权。普通成员可以读取所在空间的有效共享账号，维护人可以维护空间内容；没有恢复旧版的逐资源 / 逐账号授权。需要只向部分同事开放的资料，应放在成员范围更小的独立空间中，不能假设隐藏前端按钮就形成权限边界。

公开字段包括名称、说明、别名、标签、所属目录名称、维护人显示名、启用环境及其 URL。**一个资源勾选公开后，其所有启用入口都会公开**；本版还没有逐环境公开开关。开发、测试地址不适合公开时，应该使用独立的公开资源。公开页不返回业务用户名、密码、凭据标识、内部版本或维护人账号标识。个人主页仅在存在有效公开链接时显示。

公开搜索不使用包含停用地址的内部索引。公开检索支持可见的名称、别名、说明、标签、环境及网址；内部导航继续支持原有的拼音索引。

## 公网部署配置

`deploy/compose.yaml` 运行应用和 PostgreSQL，默认把应用 HTTP 服务映射到宿主机 `127.0.0.1:4180`；域名、HTTPS 和反向代理由部署者在 1Panel 中手动管理。数据库没有宿主机端口映射，web 容器使用非 root 用户、只读根文件系统并丢弃额外能力。应用保留请求体大小限制。

```dotenv
TEAM_NAV_ENVIRONMENT=production
TEAM_NAV_SECURE_COOKIES=true
TEAM_NAV_ORIGINS=https://nav.example.com
TEAM_NAV_ALLOWED_HOSTS=nav.example.com,127.0.0.1,localhost
TEAM_NAV_RATE_LIMIT_ENABLED=true
TEAM_NAV_REGISTRATION_ENABLED=false
```

Docker 模板已经设置这些应用保护；`deploy/.env` 中的 `NAV_DOMAIN` 仅用于生成 Host / Origin 白名单，应与最终访问域名一致。应用经 HTTP 接收代理请求，浏览器通过 HTTPS 使用 Secure Cookie。确实需要自由注册时，可另外设置 `NAV_REGISTRATION_ENABLED=true`。修改配置后运行 `docker compose up -d` 重新创建服务，刷新浏览器不能更新后端。

开发用 `start.ps1` 仅监听本机并使用 HTTP 来源，不能替代生产部署。现有数据库、凭据密钥、成员关系与公开标记均保留，不需要手工清库。

## 仍然需要明确的边界

- 这是一轮代码审查和自动化验证，不能证明“绝对安全”，也没有执行真实公网渗透测试或实际 Docker 部署。
- 数据库与凭据密钥由服务器持有，不是端到端加密。掌握服务器、数据库及密钥的人可以接触数据；超级管理员签发重置链接的能力也属于高信任权限，应严格控制。
- 暂无 MFA / OIDC、设备会话管理界面、定时备份与恢复演练。密码恢复码需要由本人离线妥善保存。
- 应用不信任任意转发 IP 头。反向代理后的账号限流仍有效，但 IP 限流可能聚合多个用户；生产环境应在可信代理处配置基于真实来源的速率和连接限制。
- 未实现每用户存储配额，也不能抵御所有流量型攻击。公网小团队部署建议保持邀请注册，定期维护依赖、基础镜像、操作系统和备份。
- 本机测试解释器为 Python 3.11.0。公网部署应使用仍在维护的最新补丁版本；依赖包审计不等于 Python 解释器和系统组件审计。
- 已经被合法下载或复制的内容不能远程收回。撤销权限会阻止后续请求，不能消除对方已经保存的数据。

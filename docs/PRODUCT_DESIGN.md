# 栖点 · 产品与交互设计

版本：v1.1 · 2026-09-14\
状态：已进入实现。账号、公开访问、协作与迁移以 [当前设计](CURRENT_DESIGN.md) 为准；下文保留完整产品规划。\
项目目录：`qidian-nav`

## 本版已落地的调整

个人身份与部门资格分开；移除成员不禁用个人账号。团队可选择成员共同维护或指定维护，公开状态与目录权限由管理员控制。个人资料支持加密导出与在另一实例导入。操作入口与准确规则见 [当前设计](CURRENT_DESIGN.md)。

浏览器收藏夹 HTML 导入、集合、OIDC、自动失效检测、定时提醒和定时备份目前尚未实现；下文相关章节为后续设计。

## 1. 要解决的问题

同事需要反复在收藏夹、群聊和文档里寻找业务后台。一个系统通常有三套环境，名称相近、链接相似，容易打开错误的环境。新人找到链接后，还需要另外询问账号。个人常用资料和团队后台又散落在不同地方。

栖点提供一个统一工作入口：**找得到、认得清环境、取得到有权限使用的账号，也有人持续维护。**

目标用户包括使用后台的普通成员、维护业务链接的负责人，以及管理部门空间的管理员。个人书签与团队链接并存，个人空间默认只有本人可见。

### 默认假设

- 首页公开内容免登录；个人账号独立，创建 / 加入部门可选。登录后管理个人资料或参与获授权的部门协作。
- 默认环境为开发 DEV、测试 TEST、生产 PROD。环境是配置数据，可以改名、排序、添加预发等环境。
- 每个系统不强制凑齐三个环境；普通书签也不必具有环境。
- 共享账号用于团队已允许共享的业务账号；导航站的访问权限与目标系统的业务权限独立。
- 初期以内网或 VPN 访问为主要部署方式，同时使用 HTTPS；不依赖公网服务获取图标或账号信息。
- 下文所有功能都纳入完整方案，开发顺序见实现计划。首批交付先覆盖可以实际使用的完整路径。

## 2. 核心产品决策

| 决策 | 具体行为 | 原因 |
| --- | --- | --- |
| 系统是主要浏览单位 | “订单中心”一张卡片，内部提供多个环境入口 | 同一个系统不会重复占据三个卡片位置 |
| 每个环境都是独立地址 | 入口上明确标注开发 / 测试 / 生产 | 不通过字符串替换域名猜测地址 |
| 点击标题查看详情 | 点击明确的环境按钮才跳转 | 不把未说明的默认环境藏在整张卡片中 |
| 账号绑定入口 | 测试账号不会自动出现在生产环境 | 环境和凭据关系可理解、可校验 |
| 私人数据默认私有 | 个人书签、个人最近访问、个人凭据归本人 | 共同使用不等于共享所有内容 |
| 浏览与维护分层 | 首页只呈现找链接所需信息，编辑使用侧面抽屉 | 保留工作入口的清晰度 |
| 搜索作为高频入口 | 支持中文、别名、拼音、标签、域名及环境组合 | 书签量大时不需要翻目录 |
| 生产环境持续可辨认 | 文字 PROD + 琥珀色标记 + 明确域名 | 降低进入错误环境的概率，避免频繁打断 |

## 3. 信息组织

```text
部门空间
├── 业务线：交易平台、用户增长、基础设施……
│   ├── 系统：订单中心
│   │   ├── 开发环境入口 → 0 到多个共享账号
│   │   ├── 测试环境入口 → 0 到多个共享账号
│   │   └── 生产环境入口 → 0 到多个共享账号
│   └── 普通书签：接口文档 / 项目看板 / 排障手册
└── 公共集合：新人入门、值班常用、发布工具箱

个人空间
├── 自己创建的书签与分组
├── 个人收藏：引用团队资源或个人资源
├── 快捷入口：固定到某个具体环境
└── 最近访问：仅本人可见，可关闭、清空
```

- 业务线负责稳定归属，标签负责横向分类，集合负责场景化整理。资源只保存一份，集合引用资源。
- 首期业务线使用一级结构，个人分组最多两级；浏览器导入的更深层级在预览时选择折叠方式，并保留原路径作为元数据。
- 系统名在同一空间和业务线内重复时提示检查，不强制全局唯一；相同名称可能是不同系统。
- 空间内同一资源、同一环境至多一个主入口。其他入口使用“关联资源”或单独的普通书签表达。
- 环境配置被使用后不能直接删除；先迁移引用或停用。修改环境名称不改变其稳定 ID。
- 原型使用演示业务线与 `.example` 地址，不代表真实部门信息。

## 4. 功能全景

### 4.1 导航与查找

| 功能 | 设计要求 |
| --- | --- |
| 业务线导航 | 左侧切换业务线，显示当前可见资源数量；可以折叠低频分类 |
| 系统卡片 | 图标、名称、简介、业务标签、负责人、明确环境入口、收藏与账号入口 |
| 卡片 / 列表 | 默认卡片，密集查看时切换列表；个人偏好跨设备保存 |
| 环境筛选 | 全部 / 开发 / 测试 / 生产 / 自定义；筛选只影响展示，不能修改任何 URL |
| 智能搜索 | 中文、英文、拼音及首字母、别名、描述、标签、域名；支持空格分词和环境词 |
| 搜索排序 | 名称精确匹配 > 别名匹配 > 前缀匹配 > 描述；个人收藏仅作为次级排序因素 |
| 搜索建议 | 可直接进入命中的明确环境，或查看系统详情；高亮匹配词 |
| 键盘操作 | Ctrl/Cmd + K 聚焦搜索，输入框外按 / 聚焦，Esc 清空或关闭当前层 |
| 收藏与置顶 | 收藏系统；单独把“订单中心 · 测试”加入个人快捷入口；个人顺序独立 |
| 最近访问 | 按个人记录具体入口，默认保留最近 30 天，支持关闭和立即清空 |
| 深链接 | 可以分享某系统详情或业务线筛选视图；接收人仍需权限，不产生公开访问权 |
| 空状态 | 区分未添加内容、无筛选结果和无访问权限；提供相应操作 |

环境筛选的明确规则：

1. 选择“测试”时，仅列出具有测试入口的系统，并只显示对应环境按钮。
2. 没有测试入口的系统不回退到其他环境；搜索仍可通过切换“全部环境”发现它。
3. 普通书签显示在单独的“通用书签”分区，不冒充某种环境，可通过资源类型筛选排除。
4. 全局筛选不改变已固定的快捷入口。快捷入口一直显示自己的环境文字。
5. 重新打开首页默认“全部环境”；业务线、排序等低风险偏好可记忆。环境筛选不隐式继承上次的生产状态。

### 4.2 页面内配置

- 首页提供“添加链接”，使用右侧抽屉完成；支持“业务系统”和“普通书签”两种资源。
- 业务系统填写名称、业务线、描述、标签、图标、负责人以及任意数量的环境地址。
- 普通书签填写名称与 URL 即可保存，分组、标签和备注选填。
- 地址必须为 HTTP 或 HTTPS；内网域名、端口、路径、查询参数均保留原意。不允许 `javascript:`、`data:` 或嵌入用户名密码的 URL。
- 同一 URL 已存在时展示可见的重复项，让用户选择复用、继续保存或合并；不泄露无权限记录。
- 编辑表单明确显示保存到“团队空间”还是“个人空间”，避免误公开。
- 默认把新增内容放入当前业务线；当前是个人空间时默认私人书签。
- 编辑系统和编辑账号是不同能力，只有对应权限的成员能打开相应操作。
- 支持调整顺序、归档、批量改业务线 / 标签、批量移入回收站；批量操作先展示影响数量。
- 保存前检查表单；保存失败保留已填写信息；未保存离开时允许继续编辑或放弃。
- 编辑使用版本号防止覆盖他人修改；冲突时展示最新版本和本次草稿，允许重新应用。

### 4.3 共享账号

**关联结构：系统 → 具体环境入口 → 一个或多个账号。**

| 字段 | 用途 |
| --- | --- |
| 账号名称 | 例如“联调用只读账号”“运营演示账号” |
| 用户名 | 邮箱、手机号、登录名等；可单独复制 |
| 密码 | 默认隐藏，按需获取；可直接复制或短时查看 |
| 用途与权限说明 | 例如“只读查询订单”“测试数据每日重置” |
| 适用团队 / 成员组 | 决定谁能获取此账号，不能超过资源本身的访问范围 |
| 维护人 | 账号失效时知道联系谁 |
| 最近更新 / 有效期 | 识别陈旧、过期账号，并提醒维护人 |
| 状态 | 可用、待核实、已过期、已停用 |
| 使用备注 | VPN、二次验证要求、并发限制、禁止改密等团队约定 |

账号面板在卡片上点击“共享账号”后打开：

1. 标题固定显示系统名称；环境切换器同时显示环境名称和域名。
2. 从某一环境打开时直接选中该环境；从卡片级入口打开时需要清晰选择环境。原型默认展示测试样例并明确标记。
3. 列出当前环境的可用账号，按用途选择；用户名、密码提供各自独立的复制按钮。
4. 点击“复制密码”才请求该凭据的明文；页面列表、搜索接口和初始 HTML 均不包含密码。
5. 显示密码需要单独操作，最长展示 20 秒；切换环境、切换账号、关闭面板、页面隐藏和登出都立即清除明文。
6. 只有剪贴板调用成功后显示“已复制”。失败时提供短时手动选择文本的方式，并解释需要 HTTPS / 浏览器授权。
7. 页面不会声称可以可靠清空操作系统剪贴板。复制后的系统剪贴板生命周期由设备和用户决定。
8. 无权获取账号时可看到“申请账号权限”入口，不能获知用户名、账号数量及敏感备注。仅在已知该系统支持申请的情况下显示申请入口。
9. 已过期和停用账号不允许获取密码；负责人更新或重新确认后恢复。待核实账号显示状态及反馈入口。
10. “账号不可用”反馈直接定位系统、环境和账号；反馈表单不要求填写密码。

一份账号确实被多个环境共用时，仍然显式维护各入口的授权绑定；用户不能因拥有测试账号权限就获得生产账号。后续可用受控的凭据复用关系减少重复维护，不能用环境间自动继承代替授权。

### 4.4 个人空间与协作

- 个人账号可独立注册；加入部门时使用管理员提供的单次有效邀请。支持退出所有设备，组织登录接入仍为后续规划。
- 本地登录提供密码修改与本人恢复码找回。部门管理员不能重置个人账号密码；导航站的登录密码与共享业务账号密码分开管理。
- 私人书签、私人分组、收藏顺序、最近访问、主题和布局偏好均属于用户。
- 团队收藏保存资源引用；链接被维护人更新后自动生效，权限被撤销后立即消失。
- 个人快捷入口绑定稳定的入口 ID。入口被停用时显示原因，不能自动跳转到另一个环境。
- 支持“推荐给团队”：先生成只包含选定书签元数据的草稿，由维护人接收；不会连带复制私人账号。
- 团队维护人可以发布一个场景集合，例如“新人入门”，其中引用文档、后台和工具。
- 普通成员可以提交新链接、修改建议、失效反馈；维护人收到站内待办。本人草稿可撤回。
- 站内通知聚合处理结果、账号即将过期、维护提醒；同类提醒合并，不干扰每日导航。

### 4.5 导入、导出与维护

| 功能 | 行为 |
| --- | --- |
| 浏览器书签导入 | 支持 Chrome / Edge / Firefox 导出的 Netscape HTML，保留标题、URL 与目录关系 |
| CSV / JSON 导入 | 提供模板；先选目标空间，再映射字段与环境 |
| 导入预览 | 展示新增、重复、无效项，逐项修正；自动推测环境只生成建议，不直接合并 |
| 去重 | 默认按完整 URL 比对并提示；不擅自删除查询参数、统一 HTTP/HTTPS 或折叠不同环境 |
| 普通导出 | 仅导出当前有权限的链接元数据，默认不包含任何账号、密码、个人历史 |
| 负责人 | 每个团队系统有维护人；可按“无人维护”“很久未确认”筛选 |
| 有效性确认 | 人工标记已核实、反馈失效，显示来源和检查时间 |
| 自动检测 | 按业务线显式启用；由能访问对应网络的服务进行，仅检查入口连通性 |
| 检测状态 | 正常、需登录、超时、无法判断、待人工确认；失败只作提示，仍可打开链接 |
| 修改历史 | 记录名称、地址、归属和维护人的修改；支持查看差异和恢复非敏感字段 |
| 回收站 | 软删除保留 30 天，可恢复资源；普通用户恢复自己的，维护人恢复授权范围内的 |
| 数据备份 | 定期备份数据库，凭据保持密文；单独管理密钥并验证恢复流程 |

自动检测不能简单把 HTTP 401/403 当成链接失效，也不能用服务端无法访问内网推断所有用户都无法访问。服务端检测必须配置允许访问的网络范围，拒绝云元数据等敏感地址，并对每次重定向重新检查目的地。

删除账号或移入回收站时立即停止获取明文。普通历史不能恢复旧密码；恢复资源后，账号恢复必须经过独立权限检查及有效性确认。

## 5. 页面结构

### 5.1 首页 / 团队导航

```text
┌──────────────┬──────────────────────────────────────────────────────┐
│ 栖点 QIDIAN  │ 工作空间 / 团队导航           帮助 · 主题 · 当前成员   │
│              ├──────────────────────────────────────────────────────┤
│ 团队导航     │ 团队的每个入口，都在这里。               + 添加链接  │
│ 我的收藏     │ 搜索系统、环境、标签或域名……                Ctrl K   │
│ 最近访问     │                                                      │
│ 个人空间     │ 我的快捷入口   订单中心·测试   日志平台·生产   接口文档│
│              │                                                      │
│ 业务线       │ 全部业务 / 交易平台 / 用户增长     全部 / 开发 / …   │
│ · 交易平台   │                                                      │
│ · 用户增长   │ 订单中心          支付网关          商品管理         │
│ · 基础设施   │ 开发 测试 生产    开发 测试 生产    开发 测试 生产   │
│              │ 共享账号   ☆      共享账号   ☆      共享账号   ☆     │
│ 管理与维护   │                                                      │
│ 空间设置     │ 通用书签   接口文档 / 团队知识库 / 发布规范          │
└──────────────┴──────────────────────────────────────────────────────┘
```

首页优先搜索和常用入口，不设置大面积欢迎插画、运营指标或复杂统计大屏。资源数量只放在分区标题和筛选结果处，帮助理解当前列表。

### 5.2 系统详情 / 账号抽屉

右侧 440–520px 抽屉，桌面保留首页上下文，移动端全屏。顶部显示系统和业务线，下面依次是环境选择、完整入口、账号列表、使用说明、负责人。详情深链接可以直接打开此抽屉。

账号信息默认折叠敏感值；复制按钮有完整文字，不能只靠小图标猜含义。环境切换会重新检查权限，并清空上一环境的敏感内容。

### 5.3 添加 / 编辑抽屉

顺序：资源类型 → 保存空间 → 基本信息 → 环境与地址 → 可选账号 → 标签及维护信息。账号字段按需展开，不强迫只添加书签的成员填写复杂表单。底部保存区固定可见，表单正文可滚动。

拥有链接编辑权限但没有账号管理权限的人，只看到链接字段；不会因修改 URL 自动获得账号访问权。变更带有账号绑定的 URL 主机或环境时，账号绑定进入“待重新确认”，维护人确认前暂停取密，防止把旧账号用于错误入口。

### 5.4 管理与维护

管理页包含业务线与环境、资源表格、成员与权限、建议与反馈、回收站、操作记录、导入导出。普通成员只看到有权限的功能，不显示不可操作的全套后台菜单。

### 5.5 个人空间

沿用首页的搜索与卡片语言，标题和可见性文字持续表明“仅自己可见”。支持自己的分组、书签、备注和可选私人凭据。复制到团队之前展示将公开的字段，账号单独选择及授权。

## 6. 权限模型

角色提供默认能力，最终权限还需同时满足空间成员关系、资源范围和账号授权。账号授权只能进一步收窄资源权限，不能扩大资源可见性。

| 操作 | 普通成员 | 业务维护人 | 空间管理员 |
| --- | --- | --- | --- |
| 查看团队链接 | 在授权范围内 | 在授权范围内 | 全空间 |
| 获取共享账号 | 额外获得账号授权后 | 额外获得账号授权后 | 额外获得账号授权后 |
| 收藏、最近访问 | 自己的数据 | 自己的数据 | 自己的数据 |
| 创建私人书签 / 凭据 | 自己的数据 | 自己的数据 | 自己的数据 |
| 提交建议 / 报错 | 可以 | 可以 | 可以 |
| 编辑团队链接 | 不能直接编辑，可提交 | 所维护业务线 | 全空间 |
| 新增 / 轮换共享账号 | 无 | 额外具有账号管理权后 | 额外具有账号管理权后 |
| 修改成员及授权 | 无 | 可建议，不可越权授予 | 可以，记入审计 |
| 查看个人空间 | 仅本人 | 仅本人 | 仅本人 |
| 查看操作记录 | 自己的相关记录 | 所管理范围 | 全空间的团队记录 |

空间管理员可以授予团队账号权限，因此属于受信任角色，授权变动记录操作者、对象和时间。系统运维人员掌握服务器与密钥时具备技术上的解密能力，本方案不宣称端到端加密或对运维人员绝对不可见。

用户离开部门后，其团队访问权和活动会话立即撤销，负责人移交团队资源。个人资料的保留与删除遵循部署时确定的组织策略，不自动公开给继任者。

## 7. 关键流程

### A. 同事进入测试后台

搜索“订单 测试” → 找到“订单中心 · 测试” → 点击明确入口 → 新标签页打开测试后台。若需要账号，在当前导航页打开账号抽屉并复制相应值。正常操作不需要中转页面。

### B. 维护人新增一个系统

点击添加 → 选择团队业务系统 → 填写名称与业务线 → 分别填写存在的环境 → 按需添加账号及用途 → 预览可见范围 → 保存。三套环境一次维护完成，不需要创建三份资源。

### C. 导入多年积累的书签

选择导入文件 → 默认导入个人空间 → 查看目录和重复预览 → 调整分组与环境建议 → 确认导入 → 结果显示新增 / 跳过 / 错误及可下载的错误清单。大导入支持任务进度和批次撤回。

### D. 账号失效

成员在对应账号点击“不可用” → 填写不含密码的说明 → 维护人收到待办 → 更新账号并确认适用环境 → 反馈者收到处理结果。新密码不进入通知内容、修改差异或错误报告。

### E. 多人同时编辑

A 和 B 同时打开某系统 → A 先保存 → B 保存收到冲突提示 → 展示当前版本及 B 的草稿 → B 重新应用并保存。页面不默默覆盖 A 的改动。

## 8. 状态与边界行为

| 场景 | 界面行为 |
| --- | --- |
| 初次使用 | 示例引导可关闭；选择手动添加或导入书签 |
| 无搜索结果 | 保留关键词与筛选，提供清除筛选和新增入口 |
| 数据加载中 | 与实际卡片尺寸一致的骨架屏，不把凭据占位成可复制值 |
| 请求失败 | 就地重试，表单草稿保留；不错误显示操作成功 |
| 会话过期 | 收起并清除敏感值，重新登录后回到原路径 |
| 链接已归档 | 显示归档说明，可从管理视图恢复；默认导航隐藏 |
| 没有某环境 | 全部环境时明确展示未配置或省略该环境；不能替换成其他环境 |
| 账号权限撤销 | 再次获取由服务端拒绝，前端清除已呈现值；已被用户复制的值无法追收 |
| 浏览器拒绝复制 | 明确反馈失败并提供可选中文本，不显示“已复制” |
| 新标签页受阻 | 保留可正常点击的真实链接，使用浏览器原生锚点跳转 |
| 导入部分失败 | 成功项与失败项分别可见，重试不重复创建成功项 |
| 长名称 / 长地址 | 名称最多两行，地址可换行或展开；复制按钮保持可见 |
| 移动端 | 左导航折叠，单列卡片，抽屉变整页，操作按钮可触达 |
| 离线 | 显示连接状态；账号不支持离线缓存；不承诺内网后台离线可用 |

## 9. 体验与性能目标

- 在约 1000 个资源、3000 个入口的部门规模下，已加载页面的本地筛选反馈目标小于 100ms；服务端搜索在约定内网环境下目标 p95 小于 300ms。
- 初次加载只获取可见资源与账号能力标记，不批量返回密码或全部账号详情。
- 列表采用分页 / 按需加载；搜索有约 180ms 防抖和旧请求取消。首屏优先 24 个资源。
- 1440px 桌面显示三列卡片，1024px 两列，窄屏一列；320px 宽度下也可使用核心操作。
- 文本对比度达到 WCAG AA，环境同时有文字与颜色，所有动作能通过键盘完成。
- 减少动画偏好生效；长表单、弹层和错误提示都有明确焦点与屏幕阅读器反馈。
- 上述是正式实现的验收目标，需要真实数据与部署环境验证；不作为静态界面稿的实测结论。

## 10. 交付验收场景

1. 创建“订单中心”，配置三个独立环境；每个按钮准确打开所填 URL。
2. 只有两个环境时不生成第三个地址；环境可以改名和排序。
3. 普通书签只需名称与 URL 即可创建，无须填写环境。
4. 首页能新增、编辑和删除有权限的资源，刷新后仍保留正式存储的数据。
5. 搜索中文、别名、拼音或域名可以命中正确资源；组合环境词能定位入口。
6. 搜索结果、数量和导出均不包含无权限资源或任何密码。
7. 复制测试账号时不会得到生产账号；切换环境清除已显示的密码。
8. 同一入口有多个账号时能按用途区分，用户名和密码能分别复制。
9. 拒绝剪贴板访问时显示失败与手动选取方式，不显示成功。
10. 已过期、停用或未授权账号不能通过直接调用接口获取明文。
11. 个人书签、个人凭据和最近访问不能被其他普通成员或空间管理员读取。
12. 收藏团队资源后，原链接变更即时反映；权限撤回时收藏不可继续打开详情。
13. 导入文件先预览，重复项不会静默覆盖，环境推测不会自动发布。
14. 默认导出无凭据、无私人访问历史，CSV 中的公式内容作为文本处理。
15. 回收站可恢复资源元数据，不因恢复而绕过账号权限或重新启用旧密码。
16. 两人修改同一资源时，后保存者收到冲突提示且不丢失草稿。
17. 后台检测超时与需要登录正确区分，检测失败不阻止用户尝试访问。
18. 取密、授权变更和资源变更具有不含明文密码的审计记录。
19. 日志、异常上报、浏览器长期存储和响应缓存均不保存明文密码。
20. 在桌面、平板和 320px 移动屏幕完成搜索、环境跳转、账号复制与添加书签。
21. 键盘能打开、操作、关闭抽屉，关闭后焦点回到触发按钮。
22. 数据库与密钥备份能在隔离环境成功恢复，并验证恢复后的授权状态。

## 11. 本轮评审重点

设计已采用合理默认值，继续实现无需重新讨论每一个小字段。最值得确认的是：三套真实环境的名称、部门有哪些业务线、哪些人能够管理共享账号，以及整体视觉是否符合团队偏好。

可交互界面稿展示首页、搜索、环境筛选、收藏、个人空间、最近访问、账号面板、卡片 / 列表、明暗主题、添加和编辑。它不具备正式的登录、授权、后端持久化或密钥服务，不能直接填入真实账号作为共享密码库使用。

# 当前账号、公开与迁移规则

版本：v1.2 · 2026-09-15。本文描述已实现的行为，包含多空间、浏览器书签导入和首轮安全改进。集合、MFA / OIDC、自动检测与定时任务仍属后续规划。

## 入口与身份

首页 `/#/` 是公开导航。浏览无需登录；需要新增、修改、收藏、查看个人资料或读取获授权账号时才登录。没有数据时呈现空状态，首次初始化入口不会妨碍游客打开首页。

个人账号 `User` 是身份主体。空间成员关系 `Membership` 是可选的附加关系，由有效邀请或空间管理员添加已有账号产生。页面和 API 根据已登录账号与当前空间的有效成员关系决定角色，不会通过设备、邮箱后缀或访问 IP 猜测某人属于哪个空间。

首次初始化创建站点所有者与超级管理员。空间名称留空时仅创建个人账号；填写名称时同时建立空间并成为管理员。超级管理员可以创建多个空间。同一账号在不同空间可以担任不同角色；切换空间会同步切换目录、资源和角色。个人资料始终归同一个账号所有。生产部署默认关闭自由注册，但有效邀请仍可注册新账号。

## 数据归属与维护

| 内容 | 归属与维护人 | 访问范围 |
| --- | --- | --- |
| 个人分组、环境、链接、私人账号 | 本人 | 默认本人；链接元数据可自行公开 |
| 个人收藏、快捷入口、最近访问、偏好 | 本人 | 本人；收藏仍遵守被引用资源的当前权限 |
| 空间目录、环境、邀请、成员、游客开关 | 空间管理员 | 当前空间的有效成员 |
| 空间链接 | 管理员、业务维护人 | 当前空间的有效成员；明确公开后也可由游客查看 |
| 空间账号密码 | 管理员、业务维护人维护 | 当前空间的有效成员可读取有效账号 |
| 全部空间状态、站点用户与账号恢复 | 站点超级管理员 | 站点管理界面只向超级管理员开放 |

目录标题旁的管理按钮可手动管理目录与环境：个人分组本人维护，最多 8 层；团队目录管理员维护，当前为一级。目录支持搜索与折叠，父目录计数包含下级目录。普通成员可以提交团队链接建议，维护人可以修改链接和账号，管理员控制目录、环境、成员及公开状态。旧版逐项授权接口已停止使用。

设置入口统一保留在侧栏底部。设置面板按“我的账号、当前空间、数据管理、站点管理”分组，各功能独立呈现；小屏设备使用分类选择器。快捷入口默认显示 6 个，可展开与整理。

## 公开的规则

个人与团队新建资源默认私有 / 团队内可见。公开是每个资源独立的明确选择，不会因开启游客入口而自动公开历史资源。

- 个人链接：本人编辑时勾选公开，出现在自己的公开页；无部门的实例首页使用站点创建者的公开资料。
- 团队链接：管理员开启空间游客访问，并把具体链接标记为公开；站点首页由超级管理员选择空间，其他公开空间可通过 `/#/w/<空间ID>` 访问。
- 关闭部门游客访问、取消资源公开、归档或删除资源后，游客不再获得该资源。
- 入口或环境停用后，其 URL 不再返回给游客或已登录的空间外部用户；没有启用入口的资源停止公开。原有公开标记保留，重新启用后可以恢复公开。
- 游客只得到选中的名称、说明、标签、分组、维护人显示名和环境链接；没有账号名称、用户名、密码、私人收藏或操作记录。

一个资源的所有启用入口都会随资源一起公开，目前不支持同一资源按环境分别公开。链接被公开不代表目标系统免登录；资源简介、目录名称与链接本身也是公开信息。账号列表不返回明文用户名；用户名与密码均需通过单独的、校验权限与状态并记录审计的访问接口读取。

## 离开部门

账号与个人资料不依赖成员资格。本人离开或被管理员移除后，当前登录仍能访问自己的导航和私人账号；团队私有资源与团队账号读取立即失效。团队公开链接仍与其他游客一样可访问。

最后一位团队管理员不能直接离开，应先交接管理员权限。即使仍是最后一位管理员，个人导航和个人导出始终可用。

空间管理员不能重置成员的个人密码；站点超级管理员可签发一次性重置链接，因此属于高信任角色。首次创建账号会生成一次性显示的恢复码；本人也可在设置中用当前密码换发恢复码。恢复密码会撤销全部会话并轮换恢复码；所有密码变更都会撤销之前未使用的重置链接。

## 个人迁移

设置与维护 → 数据管理 → 个人迁移。普通 HTML 书签文件请使用旁边的“导入浏览器书签”，可保留文件夹与跳过重复项。

1. 下载个人迁移文件；可选口令加密。包含私人账号密码时必须加密，迁移口令至少 12 位。
2. 在自己的电脑或服务器运行栖点，初始化或注册一个个人账号。
3. 选择文件并输入迁移口令，预览资源、目录、私人账号数量与重复网址。
4. 选择跳过重复项或保留两份，确认导入。

迁移包含个人分组、环境、系统与书签、可选私人账号、引用自己资源的收藏与快捷入口、主题与布局偏好。团队内容、其他人的公开资源引用、回收站、修改历史、最近访问、登录凭据与成员关系不迁移。

导入重新生成资源与账号标识，以目标个人账号为所有者；凭据使用目标密钥重新加密。导入后默认不公开，原有数据保留。相同迁移包不能重复添加。格式、URL、引用关系或解密校验失败时，整个导入不生效。

单个文件最多 10 MB；当前最多 2,000 个资源、2,000 个分组、200 个环境，每个资源最多 24 个入口，每个入口最多 50 个账号。超过限制需要先整理资料。

迁移文件是一个可导入包，目标电脑仍需要运行栖点服务。若离职后不能连回公司网络，应在失去服务器访问条件前下载迁移文件。

## 数据保存

使用 SQLAlchemy / Alembic 管理 SQL 数据库：默认 SQLite 文件；部门部署支持 PostgreSQL。正式服务不把数据只放在浏览器内存中。业务凭据为 AES-256-GCM 密文，登录密码为 Argon2 哈希，恢复码与会话令牌只保存摘要。

本机继续使用 `.env` 指定的数据位置，本次更新不清空数据库。个人资料接口按所有者隔离；数据库和服务器密钥持有者仍拥有运维层权限。详细配置与剩余边界见 [安全审查](SECURITY_REVIEW.md)。
